# O que significam 202, 503 e 504

**Em uma frase:** a API responde sobre o que **ela** fez com o comando, nunca sobre o que o robô fez fisicamente.

| Código | Significa | Não significa |
|---|---|---|
| **202 Accepted** | A API aceitou e despachou o comando. | Que o robô executou ou terminou. |
| **422** | Corpo inválido ou fora dos limites. Nada foi enviado. | — |
| **503** | Não há conexão viva com o robô. | Que a API caiu (ela respondeu!). |
| **504** | O robô não respondeu a tempo (`GO2_REQUEST_TIMEOUT_S`). Hoje só no `GET /commands/speed`. | — |

## `GET /status` é especial

O `GET /status` **sempre** responde 200, mesmo com o robô desligado (`connected: false`). É ele que diferencia "robô fora do ar" de "API fora do ar".

## Por que 202 e não esperar

1. Não travar o pipeline de voz esperando o robô se mexer.
2. A lib não tem limite de espera (timeout). Se a API esperasse a resposta de cada comando e o robô ficasse mudo, os pedidos ficariam esperando para sempre.

## Pegadinha

Um 202 com o robô parado é possível (por exemplo, `move` sem `balance_stand`). Para saber o que aconteceu de fato, olhe o robô ou o `/status`.

## Termos desta ficha

- **Código de status HTTP**: Número que resume o resultado de um pedido (2xx = ok, 4xx = erro de quem pediu, 5xx = erro do lado do servidor).
- **Timeout**: Limite de tempo de espera. Passou do limite, desiste com erro.
- **Pipeline de voz**: A cadeia do projeto que transforma fala em comando (microfone → reconhecimento → API).
- **Lib**: Biblioteca de código. Aqui, a `unitree_webrtc_connect`, que faz a conexão WebRTC com o robô.
